This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A zero-backend **personal site** deployed to GitHub Pages (`ehsankolivand.github.io`), made of **two surfaces built by one Python generator**:

1. **Portfolio** — the hand-authored `index.html` at the repo root. Committed static source; **edit it directly** (it is not generated). The build copies it into the deployed site almost verbatim.
2. **Blog** — an Obsidian-driven static site. You write Markdown in `content/blog/*.md`; `scripts/build_blog.py` renders it through `templates/blog/**` into `_site/blog/`.

There is **no framework, no bundler, no CSS/JS build step, no runtime**. The only build-time dependency is PyYAML; Markdown and syntax highlighting are done by in-house stdlib-only modules. The deployed site is plain static files served verbatim (`.nojekyll`).

## Commands

```bash
pip install -r requirements.txt                       # one-time (only PyYAML)

python -m unittest discover -s tests                  # run all renderer/generator unit tests (~107)
python -m unittest tests.test_markdown_render         # run one test module
python -m unittest tests.test_markdown_render.RenderTests.test_callout_warning  # run one test

python scripts/build_blog.py --out _site              # build the whole site into _site/
python scripts/build_blog.py --out _site --drafts     # include draft posts (local preview only)
python scripts/verify_build.py --out _site            # Definition-of-Done verifier (~594 checks) — MUST pass
python -m http.server -d _site 8080                   # preview → http://localhost:8080/blog/
```

CI (`.github/workflows/deploy.yml`) runs exactly this on every push to `main`: **unit tests → build → verify → deploy to Pages**. Any failing test or verifier check blocks the deploy. Reproduce that sequence locally before pushing.

## Architecture

### Build pipeline (`scripts/build_blog.py`)
Loads `content/blog/categories.yml` + posts → wipes and recreates `--out` (with guardrails refusing to delete the repo root or any source dir) → copies root companion files (`ROOT_COPY_ALLOWLIST`) → **regenerates only the `<!--LATEST-NOTES:*-->` region of the copied `index.html`** from the latest 3 posts → copies design assets + author media → renders each post page and the blog index → regenerates `sitemap.xml`, Atom `feed.xml`, and `llms.txt`. **Deterministic: same inputs → byte-identical output.**

### Generator modules (`scripts/blog/`)
- `config.py` — the single source of truth for site identity: base URL, author name/role, canonical JSON-LD `@id`s (`PERSON_ID`/`WEBSITE_ID`), `AUTHOR_SAMEAS`, `AUTHOR_KNOWS_ABOUT`, palettes, root-file allowlists. **These constants must stay equal to the portfolio `index.html` JSON-LD** — the verifier asserts the blog's structured-data identity *equals* the portfolio's so search/AI engines merge them into one entity. Change identity here and in `index.html` together.
- `content.py` — loads/validates frontmatter into `Post`/`Category`; raises `ContentError` (fails the build loud) on bad or missing required fields.
- `markdown_render.py` — the in-house Markdown renderer (no Markdown library). Public API: `render(md, image_resolver)`, `esc`, `esc_attr`, `sub_tokens`, `heading_slug`. Handles GFM tables, callouts/admonitions, footnotes, fenced code with info-strings, and security escaping.
- `highlight.py` — vendored build-time syntax highlighter emitting `tok-*` classes for ~10 languages; unknown languages fall back to safe escape-only output.
- `render.py` — fills the templates. Renders nav, cards, covers, index page, article page.
- `seo.py` — builds the per-page `<head>`: meta, canonical, OG/Twitter, and BlogPosting/Blog/BreadcrumbList/Person/WebSite JSON-LD.
- `sitemap.py` / `feed.py` / `llms.py` — the three generated machine-readable surfaces.

### Templating (there is no template engine dependency)
`render.py` reads `templates/blog/*.html` + `partials/*.html` and fills `{{TOKEN}}` slots via `sub_tokens` — a **single-pass** substitution: a substituted value containing `{{OTHER}}` is never re-scanned, so author text can never hijack a later slot. The design lives entirely in `templates/blog/` (HTML, `assets/blog.css`, `assets/blog.js`, self-hosted `assets/fonts/*.woff2`). Blog CSS is scoped under `#blog-root`.

### The two marker zones in the portfolio `index.html`
- `<!--LATEST-NOTES:START-->…<!--LATEST-NOTES:END-->` — the "Field notes" region, **regenerated by the build** from the latest posts. Everything outside it must stay byte-identical to source; the verifier enforces this.
- `<!--PORTFOLIO-FONTS:START-->…<!--PORTFOLIO-FONTS:END-->` — a fidelity-proven font-subset zone (unused `@font-face` subsets removed; baseline kept in `assets/portfolio-fonts/`).

Keep both zones present, paired exactly once, and structurally intact.

## Governing constraints — read before non-trivial changes

This project is **spec-driven** (Spec Kit). Its law is `.specify/memory/constitution.md` (currently **v1.5.0**), eight NON-NEGOTIABLE principles, each enforced by `verify_build.py`:

1. **SEO-correct static generation** — full content in server-rendered HTML; JS is progressive-enhancement only; all links are real crawlable anchors.
2. **GitHub Pages only** — no backend/DB/service; no new build/CI/runtime dependency.
3. **Design fidelity** — don't restyle/regenerate the look outside sanctioned bounded exceptions.
4. **Obsidian single source** — never hand-edit generated HTML; posts come only from `content/blog/**`.
5. **Per-page SEO/GEO completeness** — every page carries complete meta + valid JSON-LD; identity is unified via `@id`.
6. **Accessibility & Core Web Vitals** — one `<h1>` per page, no layout shift, compositor-only motion, `prefers-reduced-motion` honored.
7. **Non-destructive to the portfolio** — `index.html` changes only within sanctioned zones/exceptions; marker zones stay writable.
8. **Machine-readable discovery** — feed/`llms.txt`/sitemap regenerate deterministically; no committed source may link to nonexistent content.

Amendments to these principles are bounded exceptions logged in the constitution's sync report; feature specs live in `specs/NNN-*/` (spec.md, plan.md, tasks.md). The `CLAUDE.md` SpecKit block below points at the *active* feature's plan — read it for current in-flight work. Spec Kit skills (`speckit-specify`, `speckit-plan`, `speckit-tasks`, `speckit-implement`, `speckit-constitution`, etc.) drive that workflow.

## Gotchas / invariants

- **Never commit `_site/`** (gitignored) and never hand-edit anything under it — it is a rebuilt artifact.
- **Edit the portfolio in the repo-root `index.html`**, not in `_site/`. `Ehsan Koolivand - Blog.html` is the frozen original design bundle (design-fidelity source of truth), not something you edit.
- **Content authoring** is documented in `content/blog/README.md` (frontmatter schema, code-block info-strings, `[[wikilink]]` "More notes", categories, drafts). Required frontmatter: `title`, `date`, `category`, `excerpt`.
- Missing required content or a dangling internal link **fails the build/verify** by design — fix the source, don't relax the check without a constitution amendment.
- Adding a new `@font-face` family, a new color system, or client-rendered content will fail the verifier — these are deliberate design-fidelity gates, not bugs.
- Local-only, gitignored working docs (do not rely on them being deployed): `PROJECT_CONTEXT.md`, `PLUGIN_INTEGRATION_SPEC.md`, `research/`, `readme.html`, `bug-audit-resolution-report.html`.
