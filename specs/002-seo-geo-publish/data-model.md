# Data Model (delta): SEO + GEO + One-Commit Publishing

This feature adds **no new authoring fields**. The `Post`, `Category`, and `Cover` entities are
unchanged from `specs/001-obsidian-blog/data-model.md` (the authoritative definition lives in
`scripts/blog/content.py`). This file documents (a) the small derived values newly *exposed* from
existing data and (b) the shape of the new derived artifacts.

## 1. Newly exposed derived values (computed, not authored)

| Value | Source | Used by |
|---|---|---|
| `Post.word_count` | `len(re.findall(r"\w+", body))` (same tokenizer as read-time) | JSON-LD `wordCount`; feed (none); informs `timeRequired` cross-check |
| `Post.date_iso` / `Post.updated_iso` | `date.isoformat()` / `updated.isoformat()` | `<time datetime>`, Atom `published`/`updated`, JSON-LD dates |
| `Post.read_minutes` | integer parsed from `read_time` ("5 min" → 5) | JSON-LD `timeRequired` = `PT{n}M` |
| `Post.summary` | `Post.excerpt` (existing) | feed `<summary>`, llms.txt note |

These are pure functions of existing fields; they introduce no validation changes and preserve
determinism. Implementation may add them as `@property` on `Post` or as helpers in `content.py`.

## 3. Derived artifact: Atom feed (`/blog/feed.xml`)

A single Atom 1.0 `<feed>` (see `contracts/feed.md` for the exact element contract). Built from the
already-sorted (newest-first) `posts` list. Deterministic: every timestamp is a post date rendered
as `YYYY-MM-DDT00:00:00Z`; feed-level `<updated>` = `max(updated dates)` (or the portfolio date when
empty). No `today()`.

## 4. Derived artifact: `llms.txt` (`/llms.txt`)

`base = read(repo llms.txt)` (identity/profile, authored) **+** a generated trailing
`## Writing` H2 section: one `- [Title](abs_url): excerpt` item per published post, newest-first
(see `contracts/llms-txt.md`). Idempotent: any previously generated `## Writing` block in the base is
stripped before appending. When there are no posts, the `## Writing` section is omitted (base copied
through unchanged).

## 5. Derived artifact: per-page structured-data graph

Post page and index page emit an enriched JSON-LD object/graph (see `contracts/structured-data.md`)
built entirely from `Post`/`Category`/config — `BlogPosting` + `BreadcrumbList` for posts; a
`@graph` of `Blog` + `WebSite` + `BreadcrumbList` for the index — all referencing the canonical
`@id`s above.

## 6. The managed homepage region (state change)

The portfolio `index.html` managed region has two representations:
- **Committed source**: a static, **post-link-free** fallback (only a `/blog/` link). Invariant:
  contains zero `/blog/<slug>/` links.
- **Built `_site/index.html`**: the full live region (latest 3 post cards + `/blog/` link),
  deterministically regenerated by the build, unchanged in mechanism from today.

No data-model change — only the committed *content* of the region changes (links removed).
